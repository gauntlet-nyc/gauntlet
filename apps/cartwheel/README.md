# Cartwheel test fixture (owner C)

Authorized synthetic storefront (Next.js) used as the Gate test target. Demo data only; no real payment or customer accounts.

- `fixture/base/` is the baseline app (product page, checkout with a primary action `checkout-primary-action`).
- `fixture/head/` is the overlay for the "Add a floating Help button" change.
- Checkout posts one fixed synthetic item to an in-process order store and displays a receipt returned by the server. `GET /api/orders/{id}` lets local tests verify the receipt. Orders disappear when the server restarts; there is no payment or durable order database.
- `scripts/build_cartwheel_fixture.py` builds a git repo with deterministic base and head commits (fixed author, dates, no user git config) into `artifacts/cartwheel-fixture`, and with `--write-manifest` records the SHAs and a template checksum in `fixture-manifest.v1.json`. A test fails if the manifest drifts from a rebuild.
- Each generated repo must be clean when built. Its Next production build embeds that repo's full Git HEAD SHA in `GET /api/build-info`; a later checkout or runtime environment change does not alter the running build's receipt. See [build identity](../../docs/C01_BUILD_IDENTITY.md) for the exact response and limits.
- **Refund-tool change (C-02, ported from PR #11).** `fixture/refund-base/` adds a synthetic order table, an in-memory ledger and the assistant's `request_refund` tool with an ownership check; `fixture/refund-head/` removes that check. `scripts/build_cartwheel_refund_fixture.py --dest <new-dir>` builds both as two commits on `feat/assistant-refund-by-order`, branched from the registered base. The registered Help-button base/head SHAs and checksum do not change; the refund SHAs and checksum live in their own `refund-fixture-manifest.v1.json`. `npm test` in that checkout runs the node test for the tool.
- **Seven-day decision history (C-04, ported from PR #16).** `apps/cartwheel/history/` holds seeded A-04 records: decisions, tool events, ledger, KB chunks, one memory note and lineage edges, with its own `manifest.json` checksum. Regenerate with `uv run python scripts/build_cartwheel_history.py`; scoring truth goes only to `artifacts/history-truth.json` (gitignored), never into the tree.

Hidden benchmark truth must not live in this repo or its history; a test blocks obvious answer-key wording in the templates. The local headless diagnostic now exercises actual Checkout clicks and verifies server receipts on the base and at desktop width on the head. These local results do not replace B's independent oracle or Daytona/Anchor run.
