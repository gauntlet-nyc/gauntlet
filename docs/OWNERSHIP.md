# Ownership and merge-conflict prevention

**A:** `services/gauntlet/src/gauntlet/{contracts,domain,ports,application,intake,analysis,planning}/`, `packages/contracts/`, `docs/{ARCHITECTURE,CONTRACTS,RECALL}.md`, `docs/prompts/`, `docs/contracts/examples/`.

**B:** `services/gauntlet/src/gauntlet/{execution,workers,verification,recall,repair,integrations,persistence,memory,security,observability}/`, `infra/{daytona,surreal}/`, `docs/{SDK_VALIDATION,SECURITY,MEMORY,BENCHMARK}.md`, independent benchmark scorer.

**C:** `services/gauntlet/src/gauntlet/{api,reporting}/`, `apps/`, `infra/local/`, root configs, `.github/`, root scripts except `scripts/probe_*`, `docs/{PHASES,OWNERSHIP,RUNBOOK,DEMO,AGENT_HANDOFFS,DECISIONS}.md`.

**Coordinated edits:** changes to DTO/schema, security trust boundary, new root dependencies, event structures, release/approval semantics and version policy need A/B/C approval. Generated contracts can only be regenerated by A. Root/toolchain changes only by C. B may own `scripts/probe_*` files.

**Working method:** A creates schema and golden files first. B/C review and freeze. B and C code to fake fixtures, never invent their own local DTOs. Separate `git worktree`s; concise PRs; no simultaneous editing of root files. `main` is protected. Security oracle changes need an independent reviewer. Integration PR coordinated by C, not a fourth unowned conflict hotspot.

**Cross-owner handoff:** request a change as a 5-line contract issue (desired input, output, invariant, example JSON, affected consumer). A opens the formal schema PR, all approve, then generated API client is refreshed. Never patch another owner's file to unblock yourself.
